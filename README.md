# TestCaseSmartDocsHard

Локальный сервис распознавания и валидации счетов: ASP.NET Core / .NET 10, Tesseract `rus+eng`, Poppler и PdfPig. Файлы и распознанный текст не отправляются во внешние сервисы. Облачных интеграций и LLM нет.

## Запуск

Нужен Docker с Compose:

```bash
docker compose up --build -d
```

- Swagger с выбором файла: http://localhost:8091/api/swagger
- Проверка работающего API: http://localhost:8091/health
- Остановка: `docker compose down`.

При первой сборке требуется интернет для образов, NuGet и пакетов ОС. После сборки OCR работает локально. Контейнер запускается от непривилегированного пользователя, порт доступен только на localhost. Healthcheck проверяет HTTP-доступность приложения; установленные языки можно проверить командой `docker compose exec api tesseract --list-langs`.

Без Docker нужны .NET SDK 10, Tesseract с `rus` и `eng`, Poppler (`pdftoppm`) в PATH:

```bash
dotnet restore
dotnet run --project TestCaseSmartDocsHard.csproj
```

В Ubuntu зависимости OCR: `sudo apt-get install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng poppler-utils`. В Windows установите соответствующие CLI и добавьте их в PATH либо задайте абсолютные пути через `Processing__TesseractPath` и `Processing__PopplerPath`.

Настройки в `appsettings.json`, переопределяются переменными окружения:

| Переменная | Значение по умолчанию |
| --- | --- |
| `Processing__StoragePath` | `artifacts/jobs` |
| `Processing__TesseractPath` | `tesseract` |
| `Processing__PopplerPath` | `pdftoppm` |
| `Processing__ProcessTimeoutSeconds` | `60` на один CLI-процесс |
| `Processing__JobTimeoutSeconds` | `600` на задачу |
| `Processing__QueueCapacity` | `100` ожидающих задач |
| `Processing__MaxStoredJobs` | `10000` результатов до перезапуска |

## API

```bash
curl -F "file=@samples/invoice.png" http://localhost:8091/api/invoices
curl http://localhost:8091/api/invoices/JOB_ID
```

В Windows PowerShell используйте `curl.exe`.

POST возвращает `202` и `{"jobId":"..."}` после входной проверки; OCR выполняется в фоне. Повторная отправка идентичного содержимого возвращает `200` с прежним ID, в том числе при одновременных запросах или завершении задачи с ошибкой. При заполнении очереди/хранилища — `503`.

Поддерживаются PNG, JPG/JPEG, текстовые PDF и PDF-сканы, включая смешанные страницы. Максимум — 20 MiB (20 × 1024 × 1024 байт) и 10 страниц PDF. Пустой файл, неверное расширение/сигнатура, превышение лимитов, шифрование и обнаруженное повреждение PDF дают `400`. MIME-тип клиента не считается подтверждением формата. Повреждение изображения после успешной проверки сигнатуры выявляется в фоне.

GET неизвестной задачи возвращает `404`. Статусы: `accepted → processing → ready | needs_review | error`. В `ready` и `needs_review` есть `schemaVersion: "1.0"`, `document`, `issues` и `confidence`. Денежные поля — строки с двумя знаками, количество — строка без лишних нулей, отсутствующие значения — `null`. Технические ошибки содержат безопасные `code`/`message` без stderr и stack trace.

## Обработка

`InvoicesController` принимает запросы; `InvoiceIntakeService` потоково сохраняет файл и проверяет PDF. ASP.NET буферизует multipart на диск после 64 KiB. Затем вычисляется SHA-256. `JobStore` атомарно регистрирует хеш и задачу в ограниченном `Channel<Guid>` (`InvoiceQueue`), `InvoiceWorker` ожидает канал без серверного polling и обрабатывает задачи последовательно.

`DocumentRecognitionService` читает слова и координаты из PDF через PdfPig. На страницах без содержательного текстового слоя Poppler создаёт растр до 3500 пикселей по длинной стороне; Tesseract возвращает TSV со словами, блоками, координатами и уверенностью. `LocalProcessRunner` использует `ArgumentList`, без shell, с тайм-аутом и уничтожением дерева процесса при отмене. Промежуточные изображения удаляются после OCR, исходники — после завершения обработки; отклонённые и повторные загрузки удаляются сразу.

`InvoiceExtractionService` извлекает реквизиты по меткам и соседним строкам, `InvoiceTableParser` использует заголовки и координаты колонок. `InvoiceValidator` отдельно проверяет:

- контрольные цифры ИНН 10/12 знаков и банковских счетов по БИК;
- формат КПП/БИК и наличие обязательных полей;
- `qty × price = amount` и сумму строк против `amountDue`, допуск включительно `0.01`, только `decimal`;
- полноту и распознаваемость строк таблицы.

Коды ТЗ сохранены: `inn_checksum`, `account_checksum`, `line_amount_mismatch`, `total_mismatch`, `date_unparsed`. Дополнительные замечания объясняют пропуски реквизитов, неполные строки и неразобранные участки таблицы. `ready` возможен только без замечаний, с обязательными реквизитами и проверенной таблицей. Суммы НДС/без НДС не вычисляются вместо напечатанных значений.

Уверенность: OCR ниже 70 или замечание по полю → `low`; OCR от 85 и применимая пройденная проверка → `high`; остальные извлечённые поля → `medium`. Для текстового PDF оценка источника равна 100. Это объяснимая эвристика, не вероятность правильности.

## Проверка

```bash
dotnet build
dotnet test
```

xUnit проверяет контрольные суммы, денежные форматы, даты, допуски, таблицы с разными координатами и продолжением на следующей странице, JSON, очередь, отмену/тайм-ауты процессов и API. Интеграционные тесты используют настоящий текстовый PDF и ASP.NET TestServer; Tesseract для `dotnet test` не требуется.

В `samples/` находятся синтетические документы:

| Файл | Ожидаемый результат |
| --- | --- |
| `invoice.png`, `invoice.jpg` | русский счёт, две позиции, `2500.00`, `ready` |
| `invoice-text.pdf` | текстовый PDF, `ready` |
| `invoice-scan.pdf` | растровый PDF, `ready` после OCR |
| `invoice-mixed.pdf` | текстовая и растровая страницы с повторёнными позициями, `needs_review` / `total_mismatch` |
| `invoice-protected.pdf` | AES-256 PDF, `400` / `pdf_encrypted`, пароль `demo-password` |

Названия организаций и назначение этих счетов вымышлены. Корректные контрольные суммы служат тестовыми векторами, не подтверждают существование контрагента или принадлежность счёта.

Сквозная проверка работающего контейнера в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test-Api.ps1
```

Скрипт проверяет health, Swagger, все форматы, дедупликацию и отказы, сохраняет JSON в игнорируемый `artifacts/`. Повторный запуск допустим. `scripts/Generate-Samples.ps1` пересоздаёт изображения и незашифрованные PDF на Windows; защищённый пример хранится готовым. Для его пересоздания нужен только инструмент подготовки тестовых данных: `qpdf --encrypt demo-password owner-password 256 -- samples/invoice-text.pdf samples/invoice-protected.pdf`.

## Допущения и ограничения

Один процесс, одна локальная очередь, один worker; результаты и дедупликация живут в памяти до перезапуска. Удаление исходника не удаляет результат. При аварийном завершении временные файлы могут остаться в `Processing__StoragePath`; после остановки сервиса их можно удалить. Нормальная остановка отменяет активный OCR; восстановление незавершённых задач не реализовано.

Парсер эвристический: рассчитан на печатные русские счета с подписанными реквизитами и колонками наименование/количество/цена/сумма; поддержаны также базовые английские метки. RUB — базовое допущение. Рукопись, сильный перекос, плохо распознанные заголовки, сложные объединённые ячейки и нестандартное расположение реквизитов могут потребовать ручной проверки. Продолжение таблицы без повторного заголовка предполагает прежние координаты колонок. Качество OCR зависит от изображения; сервис не гарантирует извлечение любой произвольной формы. Наличие пригодного текстового слоя определяется эвристикой по числу слов и символов.

Арифметика сравнивает сумму позиций непосредственно с `amountDue` по ТЗ. Если НДС начисляется сверх сумм строк, это будет отмечено как `total_mismatch`. Авторизации нет: сервис предназначен для локального запуска, а не открытого доступа из интернета.

Для промышленного масштабирования нужны durable queue, persistent storage метаданных (например, PostgreSQL), object storage для файлов, несколько workers с распределённым захватом задач и уникальностью хеша; при необходимости Redis для блокировок, сроки хранения и observability. Локальная специализированная модель/VLM может улучшить разбор сложных форм, сохранив детерминированную финансовую валидацию.
